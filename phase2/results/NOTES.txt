AI in Medicine (MD5001) - Bowel-sound detection project
Phase 2: pretrained audio model (YAMNet) vs CRNN vs fusion, plus recall-oriented post-processing
Run: Kaggle notebook akhilanskmd24b001/notebook98cfb36f44, version 2, CPU, 372 min, finished 24 Oct 2026
Settings: --epochs 20 --seeds 1 (to fit Kaggle's CPU time limit). Same splits as phase 1.

PRETRAINED MODEL
Google YAMNet (MobileNet-v1 trained on AudioSet), attached from Kaggle Models (google/yamnet, TF2, v1); no internet needed.
YAMNet gives one 1024-d embedding per 0.96 s window (0.48 s hop). To match 10 ms labels it was run on 12 copies of
each clip shifted by 40 ms (one embedding every 40 ms), then linearly interpolated to 10 ms frames.

MODELS
yamnet_probe : frozen YAMNet embeddings -> small BiGRU head (pretrained features only)
crnn         : phase-1 CRNN on log-mel spectrogram (re-trained here, 20 epochs)
crnn_yamnet  : CRNN whose recurrent layer also receives the YAMNet embeddings (fusion)
Each scored with (a) threshold maximising frame F1, (b) threshold + median filter + minimum event length tuned for
event F1. All tuning on the inner validation split of TRAINING data only.

FINDINGS
1. The general-purpose pretrained model does NOT transfer well to bowel-sound detection: YAMNet features alone reach
   AUROC 0.86 but event F1 only 0.17-0.31. Likely reasons: bowel sounds last ~20-35 ms while YAMNet summarises ~1 s
   windows, and AudioSet contains almost no body/contact-microphone sounds.
2. Adding YAMNet features to the CRNN gives no gain (event F1 0.694 vs 0.701, within fold SD) - the task-specific
   log-mel CRNN already captures what is needed.
3. Event-oriented post-processing did not raise CRNN recall; it helps only the weak YAMNet probe (event F1 0.17 -> 0.31).
   Recall (~0.60-0.62) remains the main limitation and is consistent across folds.
4. The 20-epoch CRNN reproduces phase 1 (30 epochs, 2 seeds): grouped event F1 0.701 vs 0.703.

LIMITATIONS
Single seed; only one pretrained model (YAMNet). Models with finer time resolution (e.g. PANNs, BEATs) need internet
to download (Kaggle phone verification). No subject IDs in the dataset (grouping by recording prefix).
